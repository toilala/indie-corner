1. Introduction and Project Overview

The primary objective of this laboratory assignment is to design, develop, and deploy a complete web application that demonstrates structured multi-page navigation, modular coding practices, and appropriate CSS layout techniques as specified in Web Technology I (BIT 251, Labworks 40 & 41).

Rather than constructing a generic corporate placeholder website filled with synthetic buzzwords, I designed an Indie Game Corner—a clean, lightweight browser application where users can play three classic mini-games directly in their web browser. The application is built using fundamental, standard-compliant technologies: HTML5 for semantic page architecture, CSS3 (employing both Flexbox and Grid) for presentation, and vanilla JavaScript (leveraging the HTML5 Canvas API) for interactive game loops and form validation.

1.1 Core Objectives

  • Structured Multi-Page Navigation: Create at least three interconnected web pages (Home, About Us, and Contact) with persistent, intuitive navigation and responsive drawer support.
  • Modern CSS Layout Engineering: Implement CSS Flexbox for linear, one-dimensional element alignments (navigation bars, scoreboards, and footers) and CSS Grid for two-dimensional content structuring (game cabinets, instruction boxes, team cards, and two-column form splits).
  • Visual Styling and Accessibility: Incorporate vector icons within navigation links, apply consistent typography, maintain readable contrast, and ensure all text blocks are justified for balanced alignment.
  • Modular and Maintainable Codebase: Enforce strict separation of concerns by keeping all styling rules in an external stylesheet (style.css) and interactive behaviors in an external script (script.js), avoiding inline or internal code.
  • Native Interactive Execution: Build responsive canvas-based mini-games (Asteroid Dodge, Brick Bounce, and Classic Snake) that run at 60 frames per second without external gaming frameworks or third-party dependencies.

1.2 Scope of the Application

The application delivers a focused, highly accessible user experience. The Home page serves as the active game station with instant game-switching tabs and local high score tracking; the About Us page outlines the project rationale, technical architecture, and team contributor roles; and the Contact page provides client-side validated feedback transmission along with an expandable FAQ section.

2. Project Architecture and Modular Code Structure

Maintaining a clean and modular code organization was a core requirement during development. To ensure ease of maintainability and quick loading times, the application strictly separates structure, presentation, and behavior across five dedicated files organized in a unified directory structure:

project/ ├── index.html # Home page: Arcade game station, scoreboard & guides ├── about.html # About Us: Studio background, tech overview & team grid ├── contact.html # Contact page: Inquiry form, college details & FAQs ├── style.css # External stylesheet: CSS variables, Flexbox & Grid layouts └── script.js # External script: Canvas game loops, navigation & validation
Figure 2.1: Unified File and Directory Hierarchy

2.1 Layered Architecture

  • Content Layer (HTML5): Built using strictly semantic elements (<header>, <nav>, <main>, <section>, <article>, <aside>, and <footer>). This provides clear document outlines for assistive technologies, ensures search engine readability, and decouples content from presentation.
  • Presentation Layer (CSS3): Concentrated entirely inside style.css. It establishes CSS custom properties (design tokens) for palette consistency (--bg-page, --bg-panel, --border, --accent), eliminates redundant styling rules, and drives media-query breakpoints for responsive mobile rendering.
  • Behavior Layer (JavaScript): Authored strictly in vanilla JavaScript within script.js inside an Immediately Invoked Function Expression (IIFE) with strict mode enabled. It manages state transitions, keyboard and touch inputs, canvas frame rendering, and client-side form validation.

2.2 Sample Modular HTML Linking

3. Pages and Navigation Design

The web application consists of three interconnected pages linked through a persistent, top masthead navigation bar. The navigation is designed to provide immediate feedback on the user's current location while supporting single-click routing across pages:

  • Home Page (index.html): Hosts the interactive game cabinet with tabbed controls for Asteroid Dodge, Brick Bounce, and Classic Snake. It features real-time score and high-score readouts, interactive start/restart toggles, and three summary feature cards explaining game mechanics.
  • About Us Page (about.html): Explains the engineering philosophy behind building lightweight web games without bloated dependencies. It highlights the modular code separation and presents a 3-column team grid displaying contributor roles and project responsibilities.
  • Contact Page (contact.html): Houses a two-column layout containing college laboratory contact details on the left and an interactive message form on the right. Below the form, an informative FAQ list answers common player inquiries regarding touch devices and technology constraints.

4. Layout Techniques and Styling Decisions

The visual architecture was designed to avoid sterile, over-saturated artificial gradients in favor of a grounded, functional dark palette (slate background #10131a, panel containers #171b26, borders #262e40, and warm amber accents #f59e0b).

4.1 CSS Flexbox Implementations

CSS Flexbox is deployed across components requiring one-dimensional alignment, content distribution, and vertical centering:

  • Masthead Navigation (.nav-wrap): Uses display: flex; justify-content: space-between; align-items: center; to distribute the brand logo and navigation links.
  • Navigation Link Items (.nav-link): Utilizes inline-flex to align the 16px SVG vector icons with textual labels alongside a 0.45rem gap.
  • Scoreboard & Game Controls: Flexbox distributes score indicators and action buttons across the cabinet header and footer.
  • Footer Layout: Employs display: flex; justify-content: space-between; flex-wrap: wrap; to arrange copyright and academic credits.

4.2 CSS Grid Implementations

CSS Grid handles multi-column, two-dimensional page layouts with automatic responsive wrapping:

  • Game Overview Cards: Structured with grid-template-columns: repeat(auto-fit, minmax(250px, 1fr)); gap: 1.25rem;, automatically reflowing from three columns on desktop to a single column on mobile.
  • Team Member Grid: Arranges student contributor boxes into an adaptive responsive matrix.
  • Contact Page Layout: Splitted into a balanced 2-column grid (1fr 1fr) placing contact details beside the transmission form.

4.3 Text Justification and Typography

As emphasized in the lab requirements, text justification was implemented using a reusable utility class. Body paragraphs across all three pages apply text-align: justify; text-justify: inter-word; hyphens: auto; line-height: 1.75; ensuring straight, clean margin borders without irregular rag edges.

.text-justified { text-align: justify; text-justify: inter-word; hyphens: auto; line-height: 1.75; } .instructions-grid { display: grid; grid-template-columns: repeat(auto-fit, minmax(250px, 1fr)); gap: 1.25rem; margin-top: 2rem; }

5. Interactive JavaScript Features

All interactivity is contained in script.js using vanilla JavaScript without external libraries. Interactivity is split into three core subsystems: the canvas arcade engine, responsive navigation, and form validation.

5.1 Native Canvas Game Engine

The game station uses an object-oriented state pattern to switch between three independent games (Asteroid Dodge, Brick Bounce, and Classic Snake) sharing a single <canvas id="gameCanvas"> element:

  • Asteroid Dodge: Animates a player paddle using keyboard arrows or mouse tracking to collect falling gems (+10 pts) while dodging hazard meteors with bounding-box collision detection.
  • Brick Bounce: Simulates 2D ball reflection physics against walls, the paddle, and an array of target bricks, clearing rows upon impact.
  • Classic Snake: Implements grid-based discrete motion, snake body array manipulation, food spawning, and self-collision checks.
  • High Score Persistence: Stores high scores locally in the browser's localStorage API under unique keys, preserving scores across browser reloads.

5.3 Client-Side Form Validation

The contact form checks required inputs prior to submission. Regex validation (/^[^\s@]+@[^\s@]+\.[^\s@]+$/) verifies email addresses, character length gates enforce minimum lengths for names and messages, dynamic character counting updates live (0 / 300), and submission displays a self-dismissing success banner.
